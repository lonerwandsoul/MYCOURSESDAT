# Запуск сайта «СМП Фаворит Диван»

Инструкция для **OpenServer Panel 6** (PHP 8.4, MySQL 8.4) и без него.
Сайт запускается **без MySQL** — на резервной базе SQLite, поэтому «белого экрана»
из-за базы данных больше не бывает.

---

## 0. Что уже исправлено в проекте

| Проблема | Решение |
|---|---|
| OSP 6 «не видит» сайт в папке `home` | добавлен файл **`.osp\project.ini`** — без него панель 6-й версии проект не регистрирует |
| «MySQL недоступен: could not find driver. SQLite: could not find driver» | сайт больше не падает: подключение ищется по всем вариантам, а если драйверов нет — открывается понятная страница с инструкцией (`check.php`) |
| MySQL не подключался при `localhost` | хост MySQL определяется автоматически: модуль (`MySQL-8.4`, `MySQL-8.0`), `127.0.0.1`, порты 3306–3308 |

## 1. Быстрый старт в OpenServer Panel 6 (рекомендуется)

### Шаг 1. Положить проект в `home`

```
C:\OSPanel\home\semiglazov\        ← сюда всю папку целиком
    .osp\project.ini               ← обязательно (скрытая папка, уже есть в архиве)
    index.php
    analytics.php
    ...
```

> **Важно:** копируйте папку **целиком**. Папка `.osp` начинается с точки и в
> проводнике может быть скрыта. Если её не скопировать — проект не появится в панели.

### Шаг 2. Включить модули

Меню OSP (флажок в трее) → **Модули** → включить:

* **PHP-8.4** (или `PHP-8.4-FCGI`, если работаете через Nginx);
* **MySQL-8.4** — если нужна именно база MySQL (можно не включать: сайт уйдёт на SQLite).

То же самое из консоли OSP (меню → «Интерфейс командной строки»):

```bat
osp on PHP-8.4
osp on MySQL-8.4
osp restart
```

Имена модулей можно посмотреть командой `osp modules`.

### Шаг 3. Перезапустить панель и открыть сайт

Перезапуск: меню OSP → **Перезапустить**.

Адрес (берётся из `.osp\project.ini`):

```
http://semiglazov.local/         ← основной
http://semiglazov/               ← короткий вариант
```

Нужен другой адрес? Откройте `.osp\project.ini` и переименуйте секцию:

```ini
[my-favorit.local]
```

Панель сама добавит домен в файл `hosts`. Если появилось `DNS_PROBE_FINISHED_NXDOMAIN` —
запустите OSP от имени администратора (он не смог изменить `hosts`) или добавьте строку вручную:

```
127.0.0.1   semiglazov.local
```

### Шаг 4. Установить базу

```
http://semiglazov.local/install.php     ← кнопка «Установить базу данных»
http://semiglazov.local/check.php       ← проверка окружения (работает всегда)
http://semiglazov.local/analytics.php   ← дашборд
```

Вход: **manager / manager123** (роль «администратор»).

`install.php` создаёт базу, таблицы и демонстрационные данные автоматически —
phpMyAdmin и ручной импорт SQL **не нужны**.

## 2. Если проект не появился в списке OpenServer

Проверяйте по порядку:

1. **Есть ли `.osp\project.ini`** внутри папки проекта.
   Откройте `check.php` — он прямо пишет, найден ли файл и какие домены в нём указаны.
2. **Расширение файла.** В проводнике включите «Расширения имён файлов»:
   файл должен называться `project.ini`, а не `project.ini.txt`.
3. **Папка проекта лежит именно в `home`**, а не в `domains` (это путь OpenServer 5).
4. **Имя секции в `project.ini`** — это и есть адрес сайта. Секция `[semiglazov.local]`
   → адрес `http://semiglazov.local/`.
5. **Не указан несуществующий модуль.** В нашем `project.ini` строки `php_engine`
   и `http_engine` закомментированы специально: если написать `php_engine = PHP-8.4`,
   а такого модуля нет (например, установлен только `PHP-8.4-FCGI`), OSP **молча
   проигнорирует домен** — именно так проект «исчезает» из списка.
6. **Перезапуск.** После правки `project.ini` панель нужно перезапустить.
7. **Логи.** Меню OSP → «Логи» → `http` и `php`: там видно, отклонил ли сервер домен.

## 3. Работа без MySQL (резервная база SQLite)

Порядок выбора автоматический:

1. если в `config.local.php` / `config.php` / переменных окружения задан хост — проверяется он;
2. `127.0.0.1:3306`, `127.0.0.1:3307`, `127.0.0.1:3308`;
3. имена модулей из файла `hosts` (`MySQL-8.4`, `MySQL-8.0`, `MariaDB-…`);
4. `MySQL-8.4`, `MySQL-8.0`, `MySQL-5.7`, `MariaDB-*`, в конце — `localhost`.

Если ни один вариант не ответил (или не подключено расширение `pdo_mysql`),
сайт работает на файле `data/favorit.sqlite` — все разделы, формы и отчёты доступны.

Найденный сервер запоминается в `data/db-cache.json`, чтобы страницы не тормозили.
Включили MySQL → нажмите «Перепроверить MySQL» на `install.php` (или откройте
`check.php?refresh=1`).

**Принудительно только SQLite** — создайте `config.local.php`:

```php
<?php
return ['mysql' => false];
```

## 4. Настройка подключения к MySQL вручную

`config.php` (общие настройки, можно не трогать) и `config.local.php`
(личные настройки, в архив не попадает):

```php
<?php
return [
    'host'     => 'MySQL-8.4',   // имя модуля OSP 6 либо 127.0.0.1
    'port'     => '3306',
    'database' => 'favorit_db',
    'user'     => 'root',
    'pass'     => '',            // если задали пароль root — впишите здесь
];
```

Правила OSP 6:

* **хост — имя модуля БД**, а не `localhost`
  (`MySQL-8.4`, `MySQL-8.0`; посмотреть: `osp modules`);
* `localhost` в OSP 6 может вести на IPv6 (`::1`) — поэтому он используется
  в самом конце списка;
* пользователь по умолчанию `root`, пароль пустой.

Альтернатива файлу — переменные окружения: `DB_HOST`, `DB_PORT`, `DB_NAME`,
`DB_USER`, `DB_PASS`, `FAVORIT_MYSQL=off` (только SQLite).

## 5. Ошибка «could not find driver»

Это не ошибка сайта: в выбранной сборке PHP не включены расширения
`pdo_mysql` / `pdo_sqlite`.

**Вариант А — через панель OSP 6:**

1. Меню OSP → **Модули** → `PHP-8.4` (модуль должен быть включён, индикатор зелёный);
2. Меню OSP → **Настройки** → **PHP** → профиль вашей версии → раздел расширений;
3. включите `pdo_mysql`, `mysqli`, `pdo_sqlite`, `sqlite3`;
4. **Перезапустить** панель.

**Вариант Б — через файл `php.ini`:**

```
OSPanel\modules\php\PHP-8.4\ini\php.ini
```

Убедитесь, что строки не закомментированы:

```ini
extension=pdo_mysql
extension=pdo_sqlite
extension=sqlite3
```

**Проверка:** откройте `check.php` — там видно версию PHP, список драйверов PDO
и состояние каждого расширения. То же из консоли OSP:

```bat
php -m | findstr pdo
php -r "print_r(PDO::getAvailableDrivers());"
```

Если в списке есть хотя бы `sqlite` — сайт уже полностью работоспособен.

## 6. Запуск вообще без OpenServer

Двойной клик по **`start.bat`**:

* скрипт сам ищет PHP (`php\php.exe` рядом с сайтом → модули OSP 6 → `PATH`);
* проверяет драйверы PDO и при необходимости подключает `pdo_sqlite` вручную;
* поднимает сервер на `http://127.0.0.1:8082/analytics.php` и открывает браузер;
* данные пишет в `data\`, сессии — в `data\sessions\`.

Порт занят? Поменяйте строку `set "PORT=8082"`.

## 7. OpenServer Panel 5 (если у вас старая версия)

1. Скопируйте папку проекта в `OpenServer\domains\favorit`;
2. запустите сервер, включите PHP 8.2+ и MySQL;
3. откройте `http://favorit/install.php` → «Установить базу данных»;
4. дашборд: `http://favorit/analytics.php`.

Файл `.osp\project.ini` пятой версии не мешает — она его просто не читает.

## 8. Nginx: закрыть служебные файлы

`.htaccess` читает только Apache. Для Nginx добавьте в конфигурацию домена
(`.osp\nginx\default.conf`) блок:

**Каталог `data` закрывать обязательно** — в нём лежит резервная база
`data/favorit.sqlite`. Если Nginx отдаст её браузеру, любой посетитель скачает
все данные. Закройте служебные каталоги и файлы:

```nginx
# служебные каталоги и файлы — наружу не отдаём
location ~* ^/(data|database|\.osp)/ {
    deny all;
    return 403;
}
location ~* \.(sql|sqlite|sqlite3|ini|md|txt|bat|json)$ {
    deny all;
    return 403;
}
```

Сам сайт при этом работает как обычно: PHP читает файлы с диска, а не по HTTP.

## 10. Шпаргалка «симптом → причина → решение»

| Симптом | Причина | Решение |
|---|---|---|
| В панели OSP нет сайта | нет `.osp\project.ini` или он не скопирован | скопировать папку целиком, перезапустить OSP |
| Сайт открывается, но «как здесь оказались» / 404 | домен из `project.ini` не совпадает с адресом | открыть адрес из секции `[ … ]` |
| `DNS_PROBE_FINISHED_NXDOMAIN` | OSP не смог записать `hosts` | запустить OSP от администратора, перезапустить |
| Пропали картинки | папка `images` не скопирована / регистр букв | скопировать папку `images` |
| «Не удалось подключиться к базе данных» | нет ни `pdo_mysql`, ни `pdo_sqlite` | включить расширения (раздел 5) |
| Работает, но «SQLite · резерв» | MySQL выключен | включить `MySQL-8.4`, нажать «Перепроверить MySQL» |
| Формы не видны | гость не вошёл | `login.php` → manager / manager123 |
| После сброса демо пустые отчёты | старый баг транзакции | исправлено в этой версии; нажмите «Пересоздать демо-данные» ещё раз |
